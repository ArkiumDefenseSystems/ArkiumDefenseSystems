## ARKIUM Global Engineering Directive — Completion First (v1, 2026-11-15)

**Standing owner instruction for every current and future ARKIUM project.** Within an authorized active development session, interpret "go", "continue", "build", and "get as much done as possible" as permission to **BUILD -> INTEGRATE -> TEST -> FIX -> VERIFY -> CONTINUE** through successive eligible functional increments. Do not pause after each minor milestone to request another mission.

- First inspect the current branch, working tree, existing instructions, application entry points, and actual evidence. Respect outstanding work; never overwrite teammates' changes.
- Choose the next highest-value, unblocked feature **within the approved project scope**. Implement it end-to-end, integrate with the real app, run proportionate tests/builds and an actual runtime check when available. Keep a usable baseline.
- Once verified, advance independently to the next eligible task during the same session. Prefer functioning user workflows over reports, speculative refactors, elaborate planning, or additional scaffolding.
- If two substantive attempts fail on the same defect, stop repeating them: collect new evidence, isolate the root cause, change strategy, or mark that item BLOCKED and move to other safe independent work.
- Do not invent success, metrics, test evidence, hardware capabilities, security claims, or release readiness. Report IMPLEMENTED, TESTED, UNVERIFIED, and BLOCKED separately with relevant commands, platform and commit.
- Preserve security, privacy, offline constraints, acceptance gates and **all stricter repository-specific instructions**. Do not bypass approvals for risky/destructive operations, merges, releases, deployment, spending, credentials, external access, medical or security-critical actions.
- Request owner input **only** for genuinely missing authority, decisions, resources, unresolvable blockers, or unsafe changes; otherwise make routine engineering decisions and continue.
- At the end of the available session, provide one concise outcome-focused handoff (working functionality, evidence, remaining blockers, next actionable step). Do not imply background execution beyond the active session.

This is an execution standard, **not** permission to cross project boundaries, override safety controls, or claim untested components are finished.
